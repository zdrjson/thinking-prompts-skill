# 反向拆解

**怎么用（给助手的指令）：** 你自己按这个框架带我跑，把下面模板里的 `【】` 用我的实际情况填好再执行。对话式的框架要**一次只问一个问题**，每次追问前先用一句话说明上条回答更新了什么判断；只问可能改变结论的问题；事实/推断/观点分开写。除非我明说“把 prompt 原文给我 / 我要复制到别处”，否则不要只把模板丢回来。我有材料就一起用上。

# 反向拆解

**什么时候用:** 这东西做得真好，我想学它

```text
我想拆解的优秀范例是：【粘贴产品页面、网页、方案、流程说明、数据看板或其他成品】。我想学会的是：【填写你希望从中学会什么】。

请先用一句话说明它解决了什么问题，再反向拆解它为什么有效。

重点分析：
1. 它服务谁，目标是什么；
2. 它采用了什么结构或流程；
3. 哪些关键选择拉开了质量差距；
4. 它的完成标准是什么；
5. 哪些规律可以迁移，哪些细节只适合这个案例。

最后请给我：
1. 提炼3到5条可复用规律；
2. 一份可以照着执行的操作清单；
3. 一个最值得先尝试的小练习。
```

**要点:** 第 5 条最容易被跳过。必须让它明说哪些细节只适合原案例，不然你会把不可迁移的东西照搬走。
