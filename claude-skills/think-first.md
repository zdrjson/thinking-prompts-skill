# 第一性原理

**怎么用（给助手的指令）：** 你自己按这个框架带我跑，把下面模板里的 `【】` 用我的实际情况填好再执行。对话式的框架要**一次只问一个问题**，每次追问前先用一句话说明上条回答更新了什么判断；只问可能改变结论的问题；事实/推断/观点分开写。除非我明说“把 prompt 原文给我 / 我要复制到别处”，否则不要只把模板丢回来。我有材料就一起用上。

# 第一性原理

**什么时候用:** 方案上全是补丁，想推倒重来

```text
我想解决的问题是：【填写你的问题】。

请用第一性原理把它拆回最底层，区分：
1. 已经确认、无法绕开的基本事实；
2. 习惯性接受、却没有验证过的假设；
3. 真正想实现的目标；
4. 现实中的资源与约束。

暂时放下行业惯例和现成方案，只从基本事实、目标和约束出发，重新推导可行路径。

最后请输出：
1. 原方案中只在修补表面的部分；
2. 从基本事实重新推导出的新路径；
3. 这条路径成立的前提；
4. 验证它的第一步。
```

**要点:** 最适合处理路径依赖。改组织流程、做产品架构、修复杂系统、写代码时都好用。
